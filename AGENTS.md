# AGENTS.md — правила работы над RoadRage

## Суть проекта

RoadRage: Wasteland Survival — браузерная 2D top-down pixel-art игра на Babylon.js.
Игрок управляет вооружённым автомобилем, исследует постапокалиптический мир,
добывает ресурсы, строит базы и защищает их от рейдов. Игрок никогда не выходит
из машины.

## Обязательные команды проверки

```bash
npm run typecheck   # tsc --noEmit, strict mode
npm run test        # vitest run
npm run build       # vite build
npm run test:e2e    # production build + Playwright smoke
npm run check       # typecheck + unit + build + e2e
```

Скрипты выставляют `NODE_OPTIONS=--max-old-space-size=1024`: Babylon-типы и
production-сборка не помещаются в дефолтный heap ограниченной среды.
Playwright требует однократной установки браузера и системных зависимостей
(`npx playwright install chromium`, `npx playwright install-deps chromium`).

Не сообщать об успешных проверках, которые не выполнялись. Если проверка
недоступна, явно фиксировать это в `PROGRESS.md` и в отчёте.

## Архитектурные инварианты

1. **Симуляция не зависит от рендера.** Каталог `src/sim` и `src/core` не может
   импортировать `@babylonjs/*` или DOM. Проверяется тестами и ревью импортов.
2. **Фиксированный шаг.** `FixedStepDriver` только планирует тики; ровно один
   вызов `Simulation.step()` на тик двигает `GameTime` и мир. Шаг — 1/60 с.
   Рендер интерполирует. Двойное продвижение времени запрещено.
3. **Data-driven.** Характеристики машин, оружия, зданий, датчиков, врагов и
   экономики живут в типизированных конфигурациях `src/data`. Магические числа
   в системах запрещены, если это не локальная константа алгоритма.
4. **Разделение систем.** Транспорт, бой, мир/чанки, базы, экономика, рейды и
   удалённая симуляция — отдельные модули. Никакого «God object» `Game.ts`.
5. **Детерминизм.** Симуляция использует только seeded RNG (`SeededRandom`),
   никаких `Math.random()` и `Date.now()` внутри `src/sim`.
6. **Удалённые базы** симулируются без рендера отдельным планировщиком
   (ускоренные/агрегированные тики), результат сохраняется в состоянии мира.
7. **Сохранения версионируются.** Каждое изменение схемы сохранения требует
   миграции и обновления `SAVE_SCHEMA_VERSION`.
8. **Мультиплеер в будущем.** Ввод оформляется командами, состояние мира
   сериализуемо, системы не используют глобальные синглтоны.
9. **Мобильные браузеры** — обязательная цель. UI на HTML/CSS, управление
   touch и клавиатурой, разумный размер кадра.
10. **Временная графика допустима.** Ассеты генерируются процедурно, пока нет
    оригинального pixel-art.

## Порядок работы

- Работать строго по этапам из `docs/ROADMAP.md`. Не начинать следующий этап,
  пока текущий не проходит проверки.
- Задачи берутся из `docs/TASKS.md`; у каждой есть критерии приёмки.
- После завершения задачи обновлять `PROGRESS.md` и чекбоксы в `TASKS.md`.
- Ошибки сначала исправлять, затем фиксировать в `PROGRESS.md`.
- Не удалять работающий функционал без необходимости.

## Стиль кода

- TypeScript strict, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`.
- Иммутабельные данные в конфигах; мутабельное состояние только внутри систем.
- Экспортируемые типы — `import type`.
- Имена: `PascalCase` для типов/классов, `camelCase` для функций и полей,
  `SCREAMING_SNAKE_CASE` для констант конфигурации.
- Комментарии — только там, где объясняют неочевидное решение.
