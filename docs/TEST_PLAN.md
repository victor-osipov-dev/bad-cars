# План тестирования

## 1. Принципы

- Симуляция тестируется без браузера и без Babylon.js (Vitest, node).
- Рендер и DOM проверяются браузерными тестами, если Playwright доступен.
- Детерминизм: одинаковые seed + команды + число тиков → одинаковый снапшот.
- Не заявлять о проверке, которая не выполнялась; результат фиксируется в
  `PROGRESS.md`.

## 2. Уровни

### Юнит-тесты (Vitest)

- `src/core/math`: `clamp`, `lerp`, `moveTowards`, `Vec2`, углы, RNG.
- `src/core/time` и `src/core/loop`: `GameTime`, `FixedStepDriver`.
- Системы симуляции: движение, бой, экономика, рейды (по мере появления).
- Команды ввода: тик-упорядочивание, замена/опоздание, ограничение буфера.
- Физика машины: разгон, предел скорости, торможение, руль, ручник, коллизии,
  задний ход (включая инверсию руля и ограничение `maxReverseSpeed`).
- Раскладка клавиатуры: чистая функция `driveControlsFromKeys` (руль, реверс,
  ручник, игнорирование посторонних клавиш).
- Бой: прицеливание, интервал огня, урон, перезарядка, деспавн снарядов.
- Броня машины: урон от врагов, клампинг на нуле, разрушение, заморозка и
  респавн с полным здоровьем, детерминизм.
- Экономика: валидация конфигов ресурсов и инвентаря, добыча в радиусе и вне
  его, остановка на полном багажнике с остатком в узле, разгрузка на складе,
  сохранение суммарного количества (узел + багажник + склад), детерминизм.
- Камера: dead-zone, ограничение ареной, сглаживание.
- Миграции сохранений и валидация конфигов.
- Генерация мира: идентичность чанка при одном seed, независимость от порядка
  генерации, уникальность ключей и id пропсов, пропсы не выходят за чанк,
  препятствия только из твёрдых пропсов, чистая зона спавна.
- Стриминг: загрузка по радиусу, гистерезис (не выгружает внутри радиуса
  выгрузки), ограниченная память при длинной езде, идентичная регенерация
  после выгрузки, консистентность пропсов и препятствий.

Обязательные граничные случаи:

- отрицательный/NaN/Infinity delta;
- ровно один шаг, дробные накопления, несколько шагов;
- ограничение `maxSubSteps` и учёт отброшенного времени;
- пауза не двигает тик;
- сутки: переход через границу, точное начало суток;
- `wrapAngle` на ±π и больших углах;
- RNG: одинаковый seed → одинаковая последовательность, состояние
  восстанавливается.

### Интеграционные тесты симуляции

- N тиков → ожидаемые координаты/состояния.
- Повторный запуск с тем же seed даёт идентичный снапшот.
- Снапшот сериализуется в JSON и обратно без потерь (для будущих сохранений).
- Сценарии рейдов: победа обороны, частичный грабёж, захват.

### Браузерные тесты (Playwright, когда доступен)

- Страница загружается, ошибок в консоли нет.
- Canvas присутствует и имеет ненулевой размер.
- HUD показывает тик, который увеличивается.
- Space ставит симуляцию на паузу (тик не меняется).
- Клавиатурное вождение меняет курс и скорость, тормоз останавливает машину.
- X включает задний ход: машина едет назад, отпускание возвращает авто-газ.
- Стриминг чанков в браузере: счётчики загрузки растут, выгрузка начинается,
  активный набор не превышает лимит, HUD показывает биом и чанки.
- Добыча в браузере: подсказка появляется у узла, груз растёт при удержании E,
  панель груза совпадает с симуляцией, на площадке базы груз уходит в склад.
- На touch-устройстве видны экранные кнопки, удержание руля меняет курс.
- Resize не ломает canvas.

### Ручная проверка рендера

- Вид строго сверху, нет перспективы/наклона.
- Pixel art без сглаживания.
- Спрайты совпадают с координатами симуляции.
- HUD читаем на десктопе и мобильном.

## 3. Команды

```bash
npm run typecheck
npm run test
npm run build
npm run check
```

Playwright (конфигурация и smoke-тесты добавлены на этапе 1):

```bash
npx playwright install chromium     # один раз
npx playwright install-deps chromium # Linux, один раз
npm run test:e2e
```

## 4. Критерии готовности этапа

1. `npm run check` зелёный.
2. Новые системы покрыты хотя бы позитивным и граничным тестом.
3. Нет импортов Babylon.js/DOM в `src/core` и `src/sim`.
4. Детерминизм подтверждён тестом.
5. Результаты и ограничения записаны в `PROGRESS.md`.
